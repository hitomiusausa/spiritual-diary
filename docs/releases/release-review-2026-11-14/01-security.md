## S-01（P1・確認済み）全体の読み解き上限を1人で使い切れる

- 場所: `src/app/api/analyze/route.api.js:18-26`（IPごとは**1分**あたりの制限だけ）、`:460-466`、`:510-517`（全体のクォータ）、`wrangler.jsonc` の `DAILY_LIMIT_ANALYZE: "30"`
- 攻撃: 有効な入力（生年月日と日記1行）で `/api/analyze` に毎分10回 POST する。3分で30回に届き、そこから日本時間の0時まで、全員に `429 daily_limit` が返る。Web 版も iOS 版も読み解きできない。チャットは読み解きの結果を前提にしているので、有料の利用者も実質使えなくなる。
- IPごとの1日の上限がない。入力の検証（C-02 で修正）は、有効な入力を送る攻撃者には効かない。
- 直し方（最小）:
  1. 全体のクォータより前に、**IPごとの1日の上限**を置く（例: 1日5回。`createUserDailyQuota` と同じ仕組みで、キーは IP のハッシュ）。
  2. Cloudflare の WAF のレート制限ルールを `/api/*` の前に置く（無料プランでもルール1つは使える）。
  3. Web 版だけでも Turnstile を足すか検討する。

## S-02（P1・仕組みは確認済み・金額は推定）無料の分析で有料チャットの予算まで尽きる

- 場所: `src/app/api/analyze/route.api.js:493`・`:632-650`（`claude-sonnet-5-5`・`max_tokens: 8000`・effort medium）、`src/app/api/chat/route.api.js:118`（同じ `CLAUDE_API_KEY`）
- 単価（claude-api スキルの表、2026-11-03 時点）: Sonnet 5.5 は入力 $2・出力 $10（100万トークンあたり）。Haiku 5.5 は $0.10・$0.50。
- 見積もり: 1回の読み解きで、入力は約8〜10千トークン（人格の指示 約14KB＋プロンプト＋日記）、出力は思考を含めて最大8000トークン。1回あたり最大およそ **$0.1**。30回/日で最大およそ $3/日になり、**$20 の月の枠は約1週間でなくなる**。S-01 の攻撃を毎日くり返すだけで届く。ふつうに使われても、30回/日がずっと続けば月 $20 を超えるおそれがある。
- 枠がなくなると、Anthropic がその月のすべての呼び出しを断る。チャットも分析と同じキー・ワークスペースなので、**お金を払っている購読者のチャットも止まる**。
- 直し方（最小）:
  1. チャットと分析で API キーを分ける（ワークスペースも分けて、それぞれに上限を付ける）。これで、無料側が尽きても有料側は守れる。
  2. S-01 の IPごとの1日の上限。
  3. `DAILY_LIMIT_ANALYZE` × 1回の最大費用 × 30日 が月の予算に収まるように決め直す（使用量の実測ログはチャットにしかないので、分析にも `[kiri-usage] analyze tokens` を足すと決めやすい）。

## S-03（P2・再現済み）メモリへの切り替え中は上限が0に戻る

- 場所: `src/lib/kiriStore.js:26-38`（`incr`）。キーが2000個を超えると、**入れた順で最も古いキー**を消す。既にあるキーを数え直しても、並び順は前に出ない。
- その日の最初に作られる全体のクォータキー `kiri:q:analyze:<日付>` が、真っ先に消される。購読者ごとの `kiri:cu:` も同じ。
- 再現: `/private/tmp/claude-501/-Users-usausagi/22797482-2c82-40c4-833a-9772930ea2ba/scratchpad/review/sec-tmp/evict.mjs`
  - 30回で上限に届く → 別々のレート制限キーを2000個作る → クォータの数が **1 から数え直し**になる。
  - 出力: `before flood: allowed 30 next count 32` → `after flood: quota count restarts at 1`
- 条件: Redis が落ちたかタイムアウトしてメモリに切り替わっている間（`kiriStore.js:70-74`）。もともと Workers の isolate ごとに数えるので「全体」の上限ではないうえ、そこからさらに0に戻せる。IPv6（S-04）を使えばキーを2000個作るのはたやすい。
- 直し方（最小）: 本番・プレビュー（`isGuardedDeployEnv`）で Redis への `incr` が失敗したら、**クォータは503で閉じる**（費用側に倒す）。レート制限だけをメモリで続ける。entitlement が RC の障害時に閉じているのと同じ考え方。少なくとも `kiri:q:`・`kiri:cu:` は消す対象から外す。

## S-05（P2・確認済み）Content-Type を確かめていない

- 場所: `src/lib/apiRequest.js:15-48`（`readBoundedJson` は Content-Type を見ずに `JSON.parse` する）。ルートにもミドルウェアにも確認はない（grep で確かめた）。
- 前提の崩れ: D-21 は「他サイトの Origin はプリフライトで落ちる」としている。しかし `Content-Type: text/plain` の POST は**単純リクエスト**なので、プリフライトが起きない。ほかのサイトに置いた `fetch(..., {method:'POST', mode:'no-cors', body: JSON文字列})` がそのまま届いて処理される。応答は読めないが、費用とクォータは減る。
- 影響: 訪問者のブラウザとIPを使って枠を消せる。IPが分散するので、IPごとの制限（今の制限も、S-01 で足す制限も）が効きにくい。
- 直し方（1行程度）: `content-type` が `application/json` で始まらなければ 415 を返す（レート制限より前に置いてよい）。ブラウザは必ずプリフライトを出すようになり、CORS の許可リストが本当に効く。

## 確かめて問題がなかったところ

- **エラーの漏れ**: 両ルートとも、例外は `ApiRequestError` の固定コードか `request_failed` に置き換えている。上流の本文は `classifyProviderFailure` の固定語だけをログに出す。応答に詳細は出ない。
- **本文の大きさと JSON**: `content-length` を先に確かめ、ストリームの合計も数えて上限を超えたら 413 を返す。不正な UTF-8 や JSON は 400。`__proto__` を送っても `JSON.parse` は自分のプロパティを作るだけなので、汚染は起きない。
- **ヘッダーの偽装**: Cloudflare では `cf-connecting-ip` を最優先にしている（Cloudflare が上書きする）。`workers_dev: false`・`preview_urls: false` なので、ほかの入り口からは届かない。
- **CORS**: 許可は `capacitor://localhost` の完全一致だけ。本番では `KIRI_EXTRA_ALLOWED_ORIGINS` を無視する。`*` も Credentials も使っていない（ただし S-05 を参照）。
- **有料チャットの判定**: 本番では `KIRI_CHAT_PREVIEW` を無視する（`entitlement.js:24-29`。`wrangler.jsonc` の vars で production に固定）。権利の判定は AI を呼ぶ前で、RC の障害時は閉じる。危機の言葉への返事は AI を使わない固定文なので、権利がなくても費用はかからない。
- **時間とキー**: クォータの日付は `Intl` の Asia/Tokyo で作っている。レート制限は固定の60秒の窓（境目で最大2倍まで通るのは仕様の範囲）。
- **環境変数の読み込み**: OpenNext の `init.js` は、最初のリクエストでハンドラーを読み込む前に `process.env` を埋める。モジュールの読み込み時に読む `DAILY_LIMIT_ANALYZE`（`analyze/route.api.js:23-26`）も wrangler の値になる（変えても isolate が入れ替わるまで効かない点はチャットと違う）。
- **秘密が成果物に混ざらないか**: Worker 用は `check-embedded-env.mjs` が `next-env.mjs` の全モードが空であることを確かめ、`cf:deploy`/`cf:upload` の前に必ず走る。iOS 用は `build-ios.mjs` が `.env*` と環境変数の秘密の値を `out/` の中から探す。Web のバンドルには `NEXT_PUBLIC_*` と next.config の `env` しか入らない。`.gitignore` は `.env*`・`.dev.vars*` を除外している。
- **システムプロンプトを引き出されても**: 人格・安全・分析の指示に秘密（キーや内部URL）は入っていない。引き出されても困るものはない。
- **Upstash の設定**: `@upstash/redis` 1.39.0 は `signal` を関数で渡す形と `retry: false` に対応している（`chunk-4WQYU7T6.mjs:125-154`）。タイムアウトは効く。
