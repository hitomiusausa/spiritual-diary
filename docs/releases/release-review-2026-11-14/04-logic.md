## L-01 大運の年齢を「数え年」のまま「◯歳〜」と表示している（P2・確度 高・再現済み）

- 場所: `src/lib/saju.js:149-157`（`startAge: period.getStartAge()`）→ 画面 `src/components/SpiritualDiary.jsx:2126`（`{age}歳〜`）、プロンプト `route.api.js:563`
- 原因: lunar-javascript の `getStartAge()` は `startYear - birthYear + 1`（数え年。`node_modules/lunar-javascript/lunar.js:5930`）。
- 再現: 1988-02-15 12:00 生まれの女性、now=2031-10-20 → 表示は「己酉 44歳〜」。この大運に入る 2031-08-22（起運日の応当日）の時点で、満年齢は 43 歳。
- 影響: 日本の利用者は満年齢で読むので、毎回 1 歳ずれる。AI にも同じ数が渡り、本文で「44歳から」と書かれることがある。
- 直し方: 表示とプロンプトに使う年齢を `startYear - birthYear`（満年齢の近い値）にする。または「数え◯歳〜」と書く。

## L-04 ヒントの「色の名前・距離感・日運と時運の説明文」が乱数のままで、シードを使っていない（P2・確度 高・コードで確認）

- いつ見えるか: 端末のキャッシュが当たらないとき。たとえば、記録を 1 件消すと当日のキャッシュがまとめて消える（`SpiritualDiary.jsx:1308`）。ほかに、同じ日に 11 回以上違う入力で読み解いたとき、保存できない環境のとき、crypto.subtle がないとき。このとき同じ入力でも色の名前や距離感が変わる。色のメッセージ文だけはシードで選んでいるので、「文面は同じなのに色の名前だけ違う」ことが起きる。

## 確かめて、問題がなかったもの

- 四柱の境界
  - 立春 2024-02-04 16:26 と 16:28 で、年柱が癸卯から甲辰に、月柱が乙丑から丙寅に切り替わる。
  - 1904-02-29 23:59、1988-02-15 23:30（D-10 の夜子時方式どおり）、1900-01-01・1900-01-31 はどれも例外なく計算できる。
  - 出生時刻が空なら 12:00 で計算し、注記も正しく出る。
- バイオリズム
  - JST の暦日の差で計算している。出生日が今日なら 0/0/0。未来の日付でも壊れない。-0 は表示に出ない。
- 入力の上限
  - UI とサーバーの数え方（String.length）と上限がそろっている。trim は全角スペースも取り除く。
  - 本文の最大サイズ（制御文字のエスケープを最悪とみても約 11KB）は 32KB の上限に収まる。
- extractReplyText
  - thinking ブロックが先頭にあっても、text ブロックが分かれていても正しく取り出す。refusal と max_tokens は 502 にしていて、200 で空の結果を返すことはない。
- クライアントの流れ
  - 連打は `analysisController.current` で止めている。
  - 中止してから送り直すと、run 番号で古い応答を捨てる。
  - 90 秒の期限は本文を受け取るまで。保存中と霧の演出中は中止できない。
  - オフラインのときは通信エラーの文を出し、キャッシュが当たれば読み解ける。
  - アンマウント時に abort している。
- キャッシュ
  - キーにプロフィール全体と JST の日付が入っているので、別のプロフィールの結果が返ることはない。
  - 前日の分は読むときに捨てる。不正なペイロードは捨てる。
