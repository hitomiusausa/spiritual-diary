## 確認して問題なかったもの

- **415 の判定**: dev サーバーで、`Origin: capacitor://localhost` から `text/plain` → 415（CORS ヘッダ付き）、`application/json; charset=utf-8` → 通って 400（中身が空のため。AI は呼ばれない）。OPTIONS プリフライトは 204・`Access-Control-Allow-Headers: Content-Type`・許可オリジンを返す。画面からの送信2か所（SpiritualDiary.jsx:928・KiriChatPanel.jsx:84）はどちらも `application/json` を付けている。カウンタより前で判定している。
- **IPv6 /64**: `ipLimitKey` を15通りで確認。省略形・大文字・ゾーンID・先頭ゼロ・`::ffff:a.b.c.d`→IPv4・不正な形（`::` が2つ・括弧付き）→元の文字列のまま。IPv4 は変わらない。
- **IP ごとの1日の上限**: 入力の検証のあと・全体の上限の前に数える。キーは HMAC で IP の平文なし、TTL 2日。画面は `ip_daily_limit` でも `daily_limit` と同じ文になる（WebKit で確認）。プライバシーポリシー3節に「最長2日」が反映済み。
- **大運（saju.js）**: lunar-javascript と8件で照合（1988-02-15 女性、2000-02-29 男性、1990-12-31 23:30、1975-01-01 00:10、2025-06-01、1960-07-07 など）。最初の大運の startDate は `getStartSolar()` と一致する。startAge は満年齢（ライブラリの数え年より1少ない）。各大運は10年・10歳ずつ増える。切り替えは JST の 2031-08-21 23:00 → 庚戌、2031-08-22 00:30 → 己酉（DECISIONS の例どおり）。起運前の人は current=null で、画面は「保留」の表示になる。出力の項目名（pillar・age・startAge・endAge・startYear・endYear）は変わらず、`startDate` が増えただけなので、保存済みの履歴や端末キャッシュの古い結果もそのまま表示できる（validAnalysisPayload は taiun.age・pillar だけを見る）。
- **ヒントのシード**: `stablePicker` は FNV-1a で、同じ入力・同じ日なら同じ結果。`Math.random` は無くなった。`analysisCache.js` は変わっていないので、キャッシュのキーはこれまでと同じ。引用36文字はコードポイントで切っている。
- **応答の読み取り**: コードブロック・前後の一言・文字列の中の生の改行（LF/CRLF）は直る。閉じていない JSON・JSON が2つ・入れ子・ただの文字列は null（502 のまま）。絵文字だけ2400字超のときも、半端なサロゲートは残らない。
- **危機の正規表現**: 後読み・名前付きグループ・`\p{}` など iOS 15.5 で使えない書き方は差分の中に無い（SupportCard の `split(/(?=（)/)` は先読みなので可）。どれも単純な交互・`+` 1か所だけで、破滅的なバックトラックの形は無い。普通の日記の文約40本のうち、誤検知は上の P1-1・P2-1 のとおり。「推しが尊すぎて死ぬ」「しにものぐるい」「しんどい」などは反応しない。
- **記録の保管（quarantine）**: 壊れた1件を混ぜた履歴で読み解くと、原本が `spiritual-diary.history.quarantine.v1` にそのまま写り、読める記録＋新しい記録で保存が続く（WebKit で確認）。保管は5件まで・同じ原本は重ねない・保管場所が読めないときや写せないときは元の記録を書き換えない → 際限なく増えない、繰り返しにもならない。通常の書き出しは schemaVersion=1 のまま `unreadableHistory` が足されるだけ。その書き出しを「すべて削除」のあとに読み込むと、2件とも戻る（`validateBackupData` は知らない欄を無視するので、互換性は保たれている）。「すべて削除」で保管のキーも消え、`flushStorageWrites` の対象にも入っている。iOS では `preferences.keys()` で読み込むので、新しいキーも起動時に戻る。
- **すべて削除と書きかけ**: 入力画面から消すと書きかけは残る、結果画面から消すと入力も空になる（WebKit で確認）。
- **CSS `.kiri-hit:not(.absolute):not(.fixed):not(.sticky)`**: `kiri-hit` に `sm:absolute` などの切り替えを組み合わせた要素は無い。入力・結果のヘッダーのボタンは `position: absolute` のまま（実測）。設定・記録ボタンのタップ領域も 44px になっている。
- **React**: `ErrorBanner` は関数として呼ぶ形に直っている（フォーカスが外れる問題は解消）。差分で新しく足された「中で定義して `<X/>` で描く部品」は無い（`CollapsibleSection` は前からある）。フックの順番は変わらない。lint も通る。
- **画面が変わったときに先頭へ戻す**: 同意を断ったときに相談窓口カードへスクロールする動きは残っている（375: scrollY=879 でカードが画面内）。エラーの帯は入力画面のヘッダーの下に出て、画面の下のほうで押しても見える（top=153px）。11秒たっても消えない。

- **iOS**: `PrivacyInfo.xcprivacy` は `plutil -lint` を通り、Xcode のリソースにも入っている。RevenueCat の `setLogLevel` は失敗しても購入の設定を止めない。
- **その他**: チャットのモデルは `KIRI_CLAUDE_MODEL` か既定の Haiku だけ。ニックネームはプロンプトに JSON 文字列で1回だけ入る。未来の生年月日は、画面（はじめるボタンを押せない）と API（400）の両方で止まる。
