## P1 リリース前に直したい

### P1-1 「すべて削除」のあと、画面1枚分の空白が出る。完了の知らせも見えない
- 画像: `shots/wk375-21-after-delete-all.png`、`shots/probe-after-delete-all-result.png`、`shots/probe-after-delete-all-top.png`
- 使う人の体験: 結果画面で「最近の記録 → すべて削除 → 削除する」と進む。すると入力画面に飛ぶ。ただしスクロール位置は前のまま（scrollY=873）なので、画面の下のほうから始まる。上へ戻すと、「記録と会話をすべて削除しました」の帯の下に、画面1枚分の何もない夜色が続く
- 原因: `renderStorageNotice()` の `<aside>` に `kiri-shell` が付いている。`kiri-shell` には `min-height: calc(100vh …)` が入っている（globals.css:100）。そのため、知らせの帯が画面と同じ高さになる。保存失敗・一時保存モード・読み込めない記録のお知らせでも同じことが起きる
- なぜ困るか: 消したあとに「消えたのかな」と迷う（HIG「フィードバック」）。すぐ下に入力が続いていることも分からない
- 直し方: aside から `kiri-shell` を外す。`bg-kiri-night` 程度の背景だけを付ける。すべて削除したあとは `window.scrollTo(0,0)`。step が変わったときのスクロールも先頭に戻す
- そのままの位置で残すなら、知らせの文案: 「記録と会話を、この端末からすべて消しました。」

### P1-2 入力画面の「記録」（D-40）と「設定」、開始画面の「設定」が 44px 未満
- 測った値（WebKit / Chrome とも同じ）: 記録 66×32、設定 32×32。大きい文字では記録 76×35
- 画像: `shots/wk375-02-input.png`、`shots/wk375-01-start.png`
- なぜ困るか: HIG の 44pt に届かない（WCAG 2.5.8 の 24px は満たす）。D-40 は「オフラインでも読み返す入口」として置いたボタンなので、押しにくいと意味が弱くなる
- 直し方: 3つに `kiri-hit` を付ける。または `min-h-11 min-w-11`。見た目は変えずに当たり判定だけ広げられる

### P1-3 「すべて削除」の当たりが 66×17 と小さい。一覧を開いた直後のフォーカスもこのボタンに乗る
- 画像: `shots/wk375-13-day2-history.png`（青い枠が「すべて削除」に付いている）、`shots/wk375-09-history-list.png`
- 使う人の体験: 2日目に「記録」を開くと、最初に選ばれているのが「すべて削除」になっている。閉じる「×」のすぐ隣なので、押し間違えやすい。確認画面は出るので、データがいきなり消えることはない
- なぜ困るか: 消す操作を最初のフォーカスにしない（WAI-ARIA APG のダイアログ、HIG の破壊的操作）。小さい当たり判定（HIG 44pt）。
- 直し方: 一覧の ModalFrame に `initialFocus` を指定して、最初の記録（なければ閉じる）にする。「すべて削除」は `min-h-11 px-2` にする。置き場所は、閉じるボタンから離して一覧の下（注記の横）へ移すのがおすすめ

### P1-4 結果画面に「設定」がない。それなのに削除の確認文は「設定アイコンの…」と案内している
- 画像: `shots/wk375-06-result-full.png`（ヘッダーは見出しだけ）、`shots/wk375-20-delete-all.png`
- 使う人の体験（e）: 結果画面から「最近の記録 → すべて削除」に進むと、「バックアップは設定アイコンの『バックアップ』を選択して書き出せます」と出る。でも、その画面に歯車はない。いったん「キャンセル → 閉じる → 前の画面に戻る → 歯車」と4手かかる
- なぜ困るか: 迷わない導線ではない。案内した物が画面にない（NN/g「認識より想起」の逆）
- 直し方は次のどちらか
  - (a) 結果画面のヘッダーにも、入力画面と同じ「記録」と「設定」を置く（D-40 と対称）
  - (b) すべて削除の確認に「先に書き出す」ボタンを足す
- 確認文の案: 「消すと、もとに戻せません。残しておきたいときは、先に『書き出す』でバックアップを取ってね。」と書き、ボタンを［キャンセル］［先に書き出す］［削除する］にする

### P1-5 結果画面の最後の2つのボタンの違いが分からない
- 現状: 「前の画面に戻る」と「今日の記録をクリアする」が並ぶ。どちらも入力画面へ移る。違いは、書いた文を残すかどうかだけ（`clearAll` は入力欄を空にするだけで、履歴は消さない）
- 使う人の体験: 「クリア」という言葉から、保存した記録が消えるように読める。怖くて押せないか、思わぬ結果になる
- なぜ困るか: ボタン名は結果を正確に言う（HIG のボタンラベル、デジタル庁デザインシステム「ボタンは動作を表す」）
- 文案: 左を「書き直す」（入力を残して戻る）、右を「新しく書く」（入力を空にして戻る）にする。右の下に小さく「保存した記録は消えません」と添えてもよい

### P1-6 説明ポップアップに誤字がある

## P2 磨き

1. **結果画面の開閉ボタン 28×28**: 見出しの行全体を押せるので、指で使うぶんには困らない。キーボードで届くのは 28px の山形ボタンだけ。そのボタンに `kiri-hit` を付ければよい
2. **高さ 40px のボタンが多い**: 同意の2つ・削除確認の2つ・設定の「書き出す」「読み込む」「同意を取り消す」・結果の「最近の記録」が 40px。`py-2.5` を `min-h-11` にすると、見た目はほぼ変わらずに 44px になる
3. **文書ページの「ホームへ戻る」（105×20）と開始画面下のリンク（高さ 18px）**: `min-h-11 inline-flex items-center` にする
4. **お知らせの帯が入力画面のヘッダーに重なり、10秒で消える**: `shots/wk375-14-error-offline.png`
   - オフラインの人が「記録」を見たいときに、帯が記録ボタンにかぶっている
   - 10秒で自動的に消えるので、読む前に消えることがある（WCAG 2.2.1）
   - 直し方: 帯はヘッダーの下に出す。自動で消すのはやめるか、20秒以上にする
5. **日本語の文の中に半角スペースが入る**: privacy・terms・support で、JSX の改行がスペースとして表示されている。例「保存領域。 iOSアプリ」「ありません。 Kiri側」「JSONファイルへ 書き出して」
   - 画像: `shots/wk375-24-support.png`
   - 直し方: 1文を1行にまとめる。または行末に `{''}` を置く
6. **相談窓口カードの「（通話料有料）」が「有／料）」で割れる**（375 と 402）: `shots/wk375-17-crisis-result.png`
   - 番号と受付時間を別の行（block）に分けると、どの幅でも割れない
7. **開始画面の副題が「心の分／析ノート」で語の途中で割れ、「…心を映す／鏡」が1文字だけ次の行に落ちる**（375）: `shots/wk375-01-start-full.png`
   - 手で `<br>` は入れない
   - 直し方: 語のまとまりを `<span class="inline-block">` で包む（例「読み解く」「心の分析ノート」「映す鏡」）。または文を短くする
8. **同意文の「『読み解く』を押すと」とボタン名「Kiriに読み解いてもらう」が一致しない**: 設定の「次に『読み解く』を押したときに確認します」も同じ
   - 文案: 「『Kiriに読み解いてもらう』を押すと、…」
9. **設定の説明が、設定の中で「設定アイコンの『バックアップ』を選択して」と案内している**
   - 文案: 「自動では残らないので、大切な記録はときどき『書き出す』で保存してね。」
10. **「テーマ別運勢の算出方法」の「気分の絵文字から」**: 画面には絵文字を出していない（D-17）。「選んだ気分から」に直す
11. **四柱推命を知らない人への入口が少ない**: 開始画面の「時運分析に使います」は専門用語
    - 文案: 「生まれた時刻がわかると、いまの時間帯の流れまで読めるよ。わからなければ空けたままで大丈夫。」
12. **1280px で「タップで確認」と出る**: マウスで使う人には合わない。「開いて確認」なら、どの端末でも通じる
13. **「最近の記録」の一覧が日付だけ**: 同じ日に複数書くと見分けにくい。時刻「11月14日 21:30」を添える。詳細には気分のアイコンだけで、気分の名前がないので、名前も添える

## 歩いた場面ごとの結果

- (a) はじめての人: 基本情報 → 気分 → 同意 → 待ち画面 → 結果まで迷わずに進めた
  - 「はじめる」は生年月日がそろうまで押せない。そのことは補足文で伝わる
  - 同意を開いた直後のフォーカスは「×」（非破壊）で、適切
- (b) 2日目の人: 再読み込みすると入力画面から始まり、基本情報も残っている
  - 左上の「記録」から昨日の記録 → 詳細 → 読み解きまで読み返せた（D-40 の効果あり）
  - 小さいボタンとフォーカス位置の件は P1-2 と P1-3
- (c) 重い気持ちを書いた人
  - 同意した場合: 結果の一番上に相談窓口カードが出る。点数の欄は閉じたまま（`shots/wk375-17-crisis-result.png`）
  - 同意を断った場合: 入力の下にカードが出て、自動でそこまでスクロールする（`shots/wk375-22-declined-crisis.png`）
  - 文の調子もやわらかい。よくできている
- (d) オフライン・エラーの人: 4種類とも、入力した文は残っている
  - offline・502 →「Kiriの声が届きませんでした」、429 →「少しだけ間をおいてね」、日の上限 →「今日の読み解きは、ここまで」
  - 遅いときに「中止して入力へ戻る」を押すと、エラーを出さずに戻る
  - 帯の位置と時間の件は P2-4
- (e) 全部消したい・残したい人
  - 書き出しは `kiri-backup-YYYY-MM-DD.json` がダウンロードされ、「バックアップを書き出しました」と出る
  - 1件削除・すべて削除とも、確認の最初のフォーカスは「キャンセル」
  - 削除のあとの画面は P1-1、導線は P1-4
